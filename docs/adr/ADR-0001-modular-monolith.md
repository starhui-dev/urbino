# ADR-0001：采用模块化单体且不建立前端

状态：已接受（阶段 00）

## 决策

Urbino 以一个 Go 二进制提供数据面、管理面和 worker 的进程入口，按领域包划分边界；本阶段只开放内部健康检查，不开放模型调用。项目不创建前端，也不引入 CPA/S2A 代码或 SDK。

## 原因

模块化单体能让请求、授权、计量和账本在同一进程内保持清晰边界，同时保留后续拆分的端口。健康检查独立于模型调用，便于部署探针验证进程状态而不会绕过鉴权或配额。

## 影响

后续阶段必须通过领域端口接入 PostgreSQL、Valkey、provider 和安全 Transport；handler 不得直接更新账本或携带凭据。需要水平扩展时复用同一二进制的不同命令入口，而不是复制业务实现。

## 未采用的方案

未采用前后端分离或微服务拆分，因为阶段 00 尚无跨进程契约，过早拆分会扩大鉴权、计量和故障恢复边界。未采用 CPA/S2A 的代码、SDK 或 module；参考资料只用于安全设计取舍。

## 安全、测试与回滚

健康监听绑定回环地址，路由只包含 `/healthz`，因此不会形成绕过鉴权的模型入口。阶段测试覆盖版本输出、未知命令非零、健康响应和模型路径 404；后续阶段必须补齐鉴权、配额和真实 provider 测试。若模块化边界不适合后续扩展，可在保持 HTTP/CLI 契约的前提下把包迁移到独立进程；当前没有数据库迁移或外部状态需要回滚。
