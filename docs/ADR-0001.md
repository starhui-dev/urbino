# ADR-0001：Urbino 采用模块化单体与无前端边界

状态：accepted
日期：2026-09-18
关联阶段/需求/代码路径：阶段 00；`docs/00-scope.md`、`docs/01-architecture.md`、`cmd/urbino`、`internal/`

## 背景与约束

项目从零实现，正式名称必须为 Urbino，当前没有已确认的正式 module 域名；需要先形成可编译入口，同时保留后续 PostgreSQL、Valkey、Worker 和管理/数据面边界。产品是纯后端，不实现前端，不导入 CPA/S2A 或其他成品网关代码。

## 决策与适用范围

采用 module `example.com/urbino` 作为未确认正式路径前的本地占位；使用一个 Go 模块和一个二进制入口 `cmd/urbino`，按 `docs/01-architecture.md` 的 internal 包边界逐阶段增加能力。阶段 00 只暴露 `version`、`serve` 的内部 `/healthz`，默认监听回环地址，不提供 public、admin 或模型路由。

该决策不把 module 路径当作发布版本，也不代表已注册域名、镜像仓库或生产部署拓扑。

## 考虑过的替代方案

- 拆分多个服务：拒绝；当前阶段会增加部署和一致性边界，且规格明确采用模块化单体。
- 直接选用真实仓库域名：拒绝；仓库未提供已确认路径，猜测会污染导入、构建和文档。
- 阶段 00 暴露 public/admin 路由：拒绝；会制造未鉴权入口和假能力。

## 安全、数据一致性与授权影响

health listener 默认绑定 `127.0.0.1:9091`；配置和环境变量只覆盖监听设置，不携带凭据。阶段 00 不发起上游请求、不访问数据库、不产生账务效果。日志边界使用结构化 JSON 和敏感键脱敏，但后续仍必须遵守禁止记录正文、凭据和完整 URL 的规则。

## 测试与迁移

`go test ./...`、`go vet ./...`、`go build ./cmd/urbino` 及阶段矩阵 P00-T01..P00-T04 是本决策的初始验证入口。未来确认正式 module 路径时必须同步 project.json、导入、构建和文档，并由迁移 ADR 记录；不得默默增加兼容别名。

## 回滚与剩余风险

若后续确认正式 module 路径，按迁移计划修改当前占位并重跑全量构建/测试。剩余风险：阶段 00 尚未建立数据库、凭据、鉴权、出站和账务边界；health 地址的显式外部覆盖必须在部署阶段重新审查网络暴露。
