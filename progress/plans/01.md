# 阶段 01 实施计划

状态：in_progress

## 目标
- 建立 `internal/domain` 强类型值对象与状态/错误校验：UUID、UTC 时间、Money、币种、能力、权限 scope、tenant/project/principal/request/attempt/usage/credential version。
- 固化配置 schema、模板与显式 `URBINO_` 环境变量映射；未知字段、生产配置中的开发开关和重复 JSON key 拒绝。
- 建立 `api/admin.openapi.yaml`、可重复生成的管理契约类型与公共错误 envelope；未实现 endpoint 不提供假成功 handler。
- 定义 provider、TransportFactory、Vault、UsageObserver、Reservation、Scheduler 等最小端口及 allowed/forbidden/bounded-pass-through 字段策略文档。
- 覆盖 P01-T01..P01-T06，保存合并后真实命令证据；完成后只写 implemented，交独立 review。

## 非目标
- 不实现数据库、迁移、真实管理路由、鉴权中间件、provider 网络调用、OAuth、账务结算或任何真实上游联调。
- 不引入空实现、假成功 endpoint、map[string]any 业务 API、生成代码手工修改或生产 secret。
- 不修改前阶段无关命名和运行时行为；不提交、不部署、不跨入阶段 02。

## 不变量与金样例
- 金额为有符号解析输入但业务金额拒绝负数；微单位整数，解析乘法/加法溢出拒绝；币种仅接受明确声明且当前支持的代码。
- 状态只能按显式允许转移表推进；已完成/已停用不能回到可执行状态。
- 所有时间 UTC；UUID 输入必须是标准 UUID，生成/解析不泄露秘密。
- 错误分类至少区分 `unsupported`、`unauthorized`、`unknown`，公共 envelope 为 `code/message/request_id/retryable/details`，details 只放安全字段。
- 配置只允许已声明的 `URBINO_CONFIG`、`URBINO_HEALTH_ADDR`、`URBINO_LOG_LEVEL`、`URBINO_ENV`；不自动把所有字段映射为环境变量；production 禁止 `development`/`dev_mode` 等开关。
- JSON decoder 必须拒绝重复 key、过深结构和冲突字段；OpenAPI spec 只声明已支持管理契约，未实现接口返回稳定 unsupported，而不是 200。
- provider adapter 只构建请求/分类/解码/usage 观察；不得持有明文长期凭据、直接使用默认 http.Client 或负责收费。

## 公共契约
- `internal/domain`：值对象、错误、状态转移和最小实体/接口，纯 Go，不依赖 HTTP/SQL。
- `internal/config`：显式 `Config` schema、环境映射/优先级、模板路径；保留 `--config > URBINO_CONFIG > ./urbino.yaml`。
- `api/admin.openapi.yaml`：`info.title=Urbino`；公共错误 schema；管理资源路径只声明明确支持的契约，未实现能力不生成成功 handler。
- `api/admin_gen.go`：由锁定 `oapi-codegen` 版本生成，生成后第二次运行 diff 为空；主 Agent负责生成入口和输出校验。
- `internal/ports` 或按架构包边界定义最小 Provider/TransportFactory/Vault/UsageObserver/Reservation/Scheduler 接口，不绑定具体数据库/HTTP client。
