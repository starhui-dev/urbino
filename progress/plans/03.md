# 阶段 03 实施计划

状态：in_progress

## 目标
- 实现管理员 bootstrap 的一次性、锁保护、独占秘密输出与重复执行拒绝。
- 实现 tenant/user/project/member 与 API key 的身份边界；key 只保存 public_id、HMAC-SHA-256 摘要、pepper 版本和元数据，秘密只返回一次。
- 实现独立管理认证与 public key 认证：public key 永远不能进入 admin listener；管理角色不由请求体提升。
- 实现认证头冲突拒绝、URL/query key 拒绝、RemoteAddr 默认可信边界、认证失败限流、5 秒撤销缓存上界和 fail-closed 行为。
- 为阶段三 P03-T01..T09 建立真实测试与脱敏证据，保留前阶段回归。

## 非目标
- 不实现上游凭据 AEAD、OAuth、统一出站 Transport、Valkey 多实例 Pub/Sub、模型路由、计量结算或生产部署。
- 不读取生产凭据、不连接真实 provider、不把测试内存存储冒充生产 PostgreSQL；数据库路径必须显式 tenant/project scope。
- 不接受 URL key、不信任 X-Forwarded-For、不加入默认管理员密码或通用登录 UI。

## 公共契约与不变量
- `gw_live_<public_id>.<secret>` 为 public key 形态；secret 至少 32 随机字节，生成使用 `crypto/rand`。
- 验证先按 public_id 查找，再以独立 pepper 计算 HMAC-SHA-256，使用 `crypto/subtle.ConstantTimeCompare`；数据库不得保存完整 secret。
- public key 绑定 tenant/project/user、允许 scopes、模型策略、过期/撤销状态和 auth_version；状态、scope、租户/项目成员资格在 dispatch 前检查。
- 管理 token 使用独立表/前缀/认证路径和 scopes；管理身份不能由 public key 或请求 body 推导。
- 认证入口只接受规范头，Authorization 与协议 key 头冲突直接拒绝；query key 直接拒绝；管理 listener 与 public listener 分离。
- revocation cache TTL 最大 5 秒；缓存失效、版本不一致或 backend 不可用时拒绝，不使用无限 stale 数据。
- 资源查询必须带 tenant/project scope，跨租户/跨项目统一 404 或 permission denied，不泄漏存在性；mutation 使用版本/CAS和审计事件。
- bootstrap 使用 PostgreSQL 唯一约束/advisory lock 防双创建；输出文件必须 O_EXCL，拒绝覆盖；重复执行不能重置旧秘密。

## 测试映射
- P03-T01：public key 对 admin listener 全部失败。
- P03-T02：tenant scope 过滤列表/单项/统计。
- P03-T03：无 project member 不能引用他项目资源。
- P03-T04：撤销在 <=5 秒缓存窗口内生效，缓存不可用 fail-closed。
- P03-T05：过期或缺 scope 在出站前拒绝。
- P03-T06：并发双 bootstrap 只有一个成功且不覆盖旧秘密。
- P03-T07：Authorization/x-api-key/query-key 冲突拒绝。
- P03-T08：列表、错误、日志不含完整 key secret。
- P03-T09：同一 key 可访问多个允许模型，未允许模型拒绝。
