# 阶段 02 实施计划

状态：in_progress

## 目标
- 建立第一版 PostgreSQL migration，覆盖阶段 02 需要的租户作用域、请求/尝试、价格版本、账本基础表与核心约束；后续阶段继续追加 migration，不在本阶段实现业务流程。
- 建立显式 `urbino migrate` 的 migration runner：迁移锁、schema compatibility check、应用角色与 migrator 角色边界；应用启动不自动迁移。
- 建立带 context、statement/lock timeout 和安全错误脱敏的最小 PostgreSQL storage 边界，并提供可复用的事务 rollback 封装。
- 建立 sqlc 配置/查询目录和生成边界；若工具或真实 PostgreSQL 不可用，清楚记录 NOT_RUN，不伪造集成 PASS。
- 建立真实 PostgreSQL 集成测试入口及安全 test DSN 检查；能运行的单元/静态检查与真实 PG 检查分开记录。

## 非目标
- 不实现阶段 03+ 的租户/用户/API key 鉴权、Vault、出站、provider、OAuth、调度、流式、管理 API 或结算业务。
- 不接入真实生产数据库、不读取环境凭据、不自动启动或清理用户数据库/容器；不执行有破坏性的 schema 操作。
- 不手写或冒充 River 内部 schema；不将测试 fake 当作生产存储实现；不宣称没有真实 PostgreSQL 时集成门禁通过。

## 不变量与公共契约
- PostgreSQL 是事实来源；所有资源的跨租户引用使用 `(tenant_id,id)` 唯一键与复合外键，查询显式带 tenant/project scope。
- `requests` 的业务幂等键按 tenant 域唯一；`request_attempts` 按 `(request_id,attempt_no)` 唯一；基础 settlement 业务键预留唯一约束；价格版本发布后不可更新/删除。
- migration 使用独立 schema history 表和 advisory lock；重复运行幂等，并发 migrator 只有一个执行者；应用角色不拥有 DDL 权限的契约通过 SQL/文档表达。
- 连接/查询默认设置 statement_timeout、lock_timeout；客户端错误只返回安全分类与 request-safe message，不回显 DSN、driver 原文或密码。
- 事务 helper 在 context 取消、提交失败和回调错误时完整 rollback；短事务不持有网络调用。
- 生成代码只由锁定工具生成，生成产物不手工修改；本阶段若 sqlc 未安装/未锁定，提供配置和明确 NOT_RUN 证据，不下载未知工具代替。

## 测试映射
- P02-T01：复合外键跨 tenant 拒绝。
- P02-T02：request/attempt/settlement 业务键唯一。
- P02-T03：并发 migrator advisory lock 无竞态。
- P02-T04：应用角色无 DDL/任意账本修改权限。
- P02-T05：事务 context cancel/timeout 完整 rollback 且连接可复用。
- P02-T06：schema compatibility mismatch 拒绝启动，不自动有损迁移。
- P02-T07：DSN/driver 错误安全脱敏。

## 验证命令
- `gofmt -w` 仅作用于阶段二 Go 文件。
- `go test ./... -count=1`、`go vet ./...`、`go build ./cmd/urbino`。
- `go test ./tests/integration -count=1 -v` 或实际阶段二测试入口；无安全 test DSN/PG 时结果为 NOT_RUN/BLOCKED。
- `go run ./cmd/urbino migrate --help` 与迁移 runner 单元 smoke；不连接生产数据库。
- `sqlc generate`/`make generate-check` 仅在锁定工具真实存在并且生成配置可运行时执行。
